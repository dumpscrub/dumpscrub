Scrub pg_dump's COPY ... FROM stdin format

A default pg_dump doesn't emit INSERT statements — it emits COPY blocks with tab-delimited rows terminated by \.. Many anonymizers assume one INSERT per row and either fail or skip these. DumpScrub reads the COPY header, learns the table and columns, then streams the data rows one at a time. 

-- what pg_dump (plain format) actually looks like
COPY public.users (id, email, phone) FROM stdin;
1	jane@acme.com	+1-415-555-0199
2	\N	555-867-5309
\.

-- after: cat prod.sql | dumpscrub
COPY public.users (id, email, phone) FROM stdin;
1	quiet.rowan69@example.org	+15558324627
2	\N	+15558123944
\.

One command

$ pipx install dumpscrub
$ pg_dump --format=plain prod | dumpscrub > staging.sql
$ psql staging < staging.sql

What it gets right

  • › Parses the COPY header for table + column names (falls back to CREATE TABLE if the column list is omitted).
  • › Streams rows — flat memory even on multi-GB COPY blocks.
  • › Preserves \N (NULL) exactly.
  • › Escapes synthetic values for the text format (\t, \n, \\) so nothing corrupts.
  • › Output is still loadable by psql — the header/newline structure round-trips.

Custom / directory formats

Binary custom format (-Fc) isn't text, so convert first: pg_restore -f prod.sql dump.pgc then pipe it through. With pg_dump -Fc there's no need to pg_restore into a live database — DumpScrub works on the plain dump.
