dumpscrub vs Greenmask

Both anonymize databases — but they start from opposite ends. Greenmask connects to a live database and transforms it in place. DumpScrub transforms a dump file you already have. Pick based on where your data lives.

Capability dumpscrub Greenmask
Live DB connection requiredNoYes
ConfigurationZero-config (overrides optional)YAML
InputA dump file / stdinA running database
Postgres native COPY formatYesn/a (reads the DB)
MySQL + SQLiteYesNo
Runs air-gapped / offlineYesPartial
Single-binary / one-commandYesDocker + config
CI gate + audit-evidence reportProNo
Subsetting, transformations dsl, determinism per-runSimpler setRicher

Choose Greenmask if…

  • › You have a reachable database and want in-place transforms.
  • › You need subsetting, complex transformation rules, or per-run randomization.
  • › You're already comfortable maintaining YAML and Docker.

Choose dumpscrub if…

  • › Your data is a dump file (from prod, a vendor, or a backup) and you don't want to stand up a DB to scrub it.
  • › You want it in CI — line in, line out, exit codes, no config.
  • › You need it to run air-gapped or you handle MySQL/SQLite too.
